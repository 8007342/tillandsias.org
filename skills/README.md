# Skills

Canonical home of the procedures an agent follows to keep this site honest.
One source of truth: every harness reaches a skill through a symlink into this
directory (`.claude/skills/<name>` and `.opencode/skills/<name>` point here), so
what an agent can do does not depend on which harness launched it. The
`openspec-*` skills under the harness directories are the exception: they are
generated by the `openspec` CLI at launch, not authored here.

| Skill | Use it when |
|---|---|
| [`update-website`](update-website/SKILL.md) | Weekly, or after a Tillandsias release: re-verify the pages against the newest release and move the pins. The bootstrap. |
| [`audit-site-claims`](audit-site-claims/SKILL.md) | Re-verifying one level's footnotes, quotes and flags against a checkout at a given tag, with an adversarial second pass. |
| [`file-issue`](file-issue/SKILL.md) | Recording one defect in the `issues.d/` ledger, moving it along, or retracting a published claim. |
| [`file-findings`](file-findings/SKILL.md) | Recording what the audit found so it survives the forge, and getting it in front of the runtime project. |

The helper scripts under `update-website/scripts/` are POSIX shell over `git`,
`curl` and `jq`. Two tools are Python: the page build this repository
inherited, and `scripts/issues.py`, which folds the findings ledger. The
runtime's methodology forbids Python for its own committed automation, and this
repository is the exception rather than a counter-argument — the ledger fold
has to run inside the build, and the build is already Python. A rewrite is
recorded as a finding, not waved away.

Every gating script prints a one-line machine-readable verdict on its last line
and exits non-zero on anything that should stop a publish:
`ok:checked-build`, `ok:up-to-date`, `drift:<levels>:<broken>`,
`blocked:missing-checkouts:<tags>`, `blocked:footnotes-do-not-resolve`,
`blocked:targets-unchecked`, `blocked:build-warnings`,
`ok:issues:<n> finding(s)`, `violation:issues:<n>`. Two scripts return a value
rather than a verdict and say so in their own headers: `latest-release.sh`
prints a tag, `pinned-refs.sh` prints one `slug<TAB>tag` per level.
