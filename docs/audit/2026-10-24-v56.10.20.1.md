# Website re-verification — v56.10.20.1

Stable moved from `v56.10.9.1` to `v56.10.20.1` (promoted 2026-10-20). All five
levels were re-verified against the new tag and moved in one pass. Everything
below was **read in code** at the tag. Nothing was tested live for this audit.

This pass also applied an editorial rule, recorded in `docs/matrix/README.md`
since September and now enforced across the non-level pages too: the site
describes the architecture and the method, not the project's own operations.
Machine names, work-queue mechanics, internal identifiers and the dated work
log behind a finding are not reader material; where they appeared in page
prose or page furniture they were removed or generalised. Footnote targets
still carry whatever path the runtime repository uses, identifiers included,
because a reader clicking one must land on the cited line.

## Flags re-decided

- **Phone: the Mac reset RED is retired.** At this release every installer
  runs the soft reset only. The macOS installer's own comment says it keeps
  the VM, the Vault store, the sign-ins and the downloads; the macOS tray's
  hard reset, which does destroy the store, needs explicit approval and is
  reachable from no installer. The paragraph that told readers to set
  `TILLANDSIAS_DESTRUCTIVE_RESET_OK=0` was wrong for this release (the
  installers no longer prompt and nothing they run deletes a store) and was
  rewritten.
- **Power user: the browser section was rewritten.** The agent's browser tool
  no longer looks for a host Chromium: every window is the framework
  container, started by the host, reaching the display over Wayland only, and
  running headless when there is no display or on request. The old RED (a
  host Chrome nothing installs) is retired. A new RED records that the browser
  spec still says JavaScript evaluation is disabled in this version while the
  code enables it for development-mode windows. The orphaned Chrome installer
  script is still in the tree and still cited.
- **Power user: the publish RED was reshaped.** A publish that needs a missing
  image now builds it on first use and reports the step, and a failed build is
  remembered so the next attempt waits for the retry; the earlier "initialise
  the managed runtime image" refusal is gone, and a test pins that. The draft
  status of the preview spec, the never-run publish litmus and the apex route
  stay RED.
- **Power user: vault wording.** The unseal share now reaches the vault as a
  file on tmpfs for the length of the launch, never as a podman secret. The
  spec citation and two sentences were updated to say so.
- **Security: the browser GREEN was rewritten and paired with a RED.** GREEN:
  the browser an agent drives is a container, and a build check refuses any
  code path that hands a URL to a host browser; evaluation is refused outside
  a development-mode window. RED: the spec has not caught up with that mode.
- **Security: a sentence on secret transport was added.** Credential material
  that crosses the host–container boundary is no longer a podman secret
  (podman's file driver keeps it in plaintext on durable disk); the spec and
  the launcher are cited.
- **Security: two footnotes moved to a Lua port.** The litmus-step scanner is
  now `scripts/lua/check-litmus-steps-can-fail.lua`; the claims did not change.
- **Security: the fallback-share RED is unchanged.** The guest still writes
  the share to a fallback file in its cache directory, and the spec still
  forbids a persisted one. Linux-host plaintext at rest was addressed in this
  release, but the cited guest-side writes remain, so the flag stands.
